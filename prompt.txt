GOAL AND PROBLEM
MarketTrace answers: When an incoming market-data stream becomes incomplete or wrong, can we detect the issue, reconstruct a trustworthy state, and identify precisely which downstream analytics need correction? Build one BTC-USD order-book incident and replay system. C++ owns the immediate market state; Snowflake is the historical evidence and analytical warehouse; an extended DepGraph owns explicit calculation-dependency and affected-window analysis; a small local dashboard explains the incident and recovery. This is an engineering and data reliability study, not a trading bot, alpha strategy, broker integration, or FPGA project.

CORE DELIVERABLE AND USER FLOW
An engineer starts a reproducible recorded experiment. The UI shows a correct book, best bid/ask, midpoint and spread. The experiment injects a missing or malformed update. The engine records a precise incident and invalidates only calculations whose required evidence is affected. The dashboard shows the raw event, decision, affected calculation window, and reason. A valid source snapshot restores current book state from its own point in time but leaves earlier missing-history windows incomplete. In a separately labeled controlled fixture branch, restoring the genuinely withheld event permits those affected historical windows to be recomputed as new revisions. The engineer can replay both branches and compare outputs with the independent reference. A later bounded live-capture mode uses the same processing path. Snowflake does not sit in the immediate C++ update path, and the dashboard is never described as an HFT system.

EXACT METRIC SPECIFICATION TO FREEZE BEFORE TUNING
Snapshot and updates contain integer price ticks and integer sizes. Reject nonpositive prices, negative sizes, unknown sides, crossed/empty best quotes according to documented book rules, and any invalid snapshot. Define best bid b and best ask a only for a valid nonempty book; midpoint m=(a+b)/2 in exact scaled arithmetic; spread s=a-b; optional spread in basis points=10000*s/m when m>0. For a controlled fixture, construct 11 consecutive, valid midpoint observations at predeclared 1-second sample times; 10 log returns r_i=ln(m_i/m_(i-1)); report sample standard deviation sqrt(sum((r_i-r_bar)^2)/(10-1)) without annualization. A missing required observation blocks the exact window rather than silently forward-filling. Event-time, sample cadence, duplicate/late policy, precision and rounding must be fixed before evaluation. Real live feed has irregular updates: either explicitly resample with a documented completeness rule or omit live volatility until enough valid samples exist. Crossed quotes may indicate either invalid state or a provider-specific condition; follow source semantics and document the policy rather than assuming every crossed event is an exchange error.
